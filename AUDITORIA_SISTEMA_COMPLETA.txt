## 2. `c:\xampp\htdocs\IT_Software\config\security.php`
- **Full Path:** `c:\xampp\htdocs\IT_Software\config\security.php`
- **Line Count:** 73 lines
- **Purpose:** Defines the `Security` utility class with static `encrypt($data)` and `decrypt($encryptedData)` methods using OpenSSL `aes-256-cbc` and a prepended random IV encoded in Base64.
- **Encryption Key Management Check:** **HARDCODED** on line 10 (`private static $encryption_key = 'b23a9d9431ec5e963bc1843ad8ea607f2df47bfd62054c30c8da26e2e5e1a3d9';`). It is **not** environment-based, despite the warning comment on line 9.
- **Security Issues:**
  - **Hardcoded Credentials/Key:** The 256-bit AES symmetric key is committed directly in source code (`config/security.php` is not ignored by `.gitignore`), allowing anyone with source/backup access to decrypt all stored passwords and PINs.
  - **Weak Encryption / Missing Integrity:** Uses `aes-256-cbc` (lines 23, 49) **without** an HMAC (Encrypt-then-MAC) or authenticated cipher (`aes-256-gcm`). This leaves ciphertexts vulnerable to undetected tampering, IV bit-flipping, and potential padding-oracle behavior.
  - **Weak Randomness Check:** Line 28 calls `openssl_random_pseudo_bytes($iv_length)` without verifying the `$crypto_strong` flag (`random_bytes()` is preferred).
  - **SQL Injection / XSS / CSRF:** N/A.
- **Best Practices Violations:**
  - No key versioning or rotation mechanism.
  - Missing strict scalar/return type hints on `encrypt()` and `decrypt()`.
  - Re-computes `hex2bin(self::$encryption_key)` on every invocation without checking for `false`.
  - Returns `''` silently on decryption failure (line 71), making failure indistinguishable from empty data.
- **Missing Validations:**
  - Line 53 calls `base64_decode($encryptedData)` without `$strict = true` and without checking for `false` return before `strlen($raw_data)`.
  - Line 45 uses `empty($encryptedData)` (treats `'0'` as empty).
  - Line 58 checks `strlen($raw_data) <= $iv_length`, whereas valid AES-CBC PKCS#7 ciphertext requires at least `iv_length + 16` bytes and block-size alignment.
  - Does not verify `openssl` extension availability or check if `openssl_encrypt()` (line 31) returns `false`.
- **Error Handling Quality:** Minimal. Silently returns `''` on invalid input, short payload, or `openssl_decrypt()` failure without logging or throwing exceptions; fails to guard against `openssl_encrypt() === false` or `base64_decode() === false`.

# Comprehensive Code & Architecture Audit: Main Pages & Core Layout

## Executive Summary
An end-to-end audit of the 5 core files in `c:\xampp\htdocs\IT_Software` reveals a clean, functional modern Tailwind-based UI with several notable structural, performance, security, and consistency issues:
1. **Dashboard DB Efficiency (`index.php`)**: Executes **17 separate SQL queries** (8 against `equipos` alone) *before* authentication is even checked in `includes/header.php`. Most KPIs and breakdowns can be consolidated into 2–3 queries.
2. **Broken/Misleading Links**: `index.php` links to `modules/credenciales/index.php?tab=equipos` (which redirects to `modules/empleados/index.php`, not equipment credentials) and omits filter query parameters on company/city KPI links despite tooltip promises. `modules/usuarios/index.php` exists and is matched in `header.php`'s active-state logic, yet has no navigation item.
3. **CSS / Tailwind Mismatches**: Multiple files rely on `shadow-xs` (Tailwind v4 utility absent in Tailwind v3 CDN), `.animate-fade-in-up` (defined inline only in `index.php`, missing on other pages where `header.php` flash messages use it), `.glass-panel` (undefined), `.custom-scrollbar` (undefined), and invalid CSS `ring` / `ring-color` properties in `header.php`.
4. **Misplaced File (`includes/plantilla.php`)**: Contrary to its name and location, `includes/plantilla.php` is **not a UI template system**—it is a standalone CSV download endpoint for Excel import templates.
5. **Inline JS & Error Handling (`footer.php`, `index.php`)**: 315 lines of global JS are inline in `footer.php`, `TablePaginator` lacks `NaN` validation on `localStorage` values and HTML-escaping on `itemLabel`, and `pageshow` forces full reloads on bfcache restore.

## Executive Summary of Critical Findings

Worse, `equipos/guardar.php?action=baja&id=...` and `entregas/guardar.php?accion=eliminar&id=...` perform destructive mutations over `GET`, and `entregas/guardar.php` accepts `GET` for *all* actions (`crear`, `entregar`, `editar`, `eliminar`) because it never checks `$_SERVER['REQUEST_METHOD']`.

   - **Sensitive Data Exposure:** Line 523 serializes `pc_pin_clear` (decrypted Windows PC PINs) and `pc_pin_cifrado` into the HTML DOM `onclick` attribute for every assigned equipment row.
4. **DDL & Seed Data Execution on Every Page Load (`entregas/index.php`):** Lines 12–44 execute `CREATE TABLE IF NOT EXISTS` and re-insert hardcoded dummy records whenever `recepciones_equipos` is empty.
5. **Unvalidated File Upload, Hardcoded Import Logic & N+1 Queries (`equipos/guardar.php`):** `import_csv` lacks MIME/size/extension allowlisting, uses `simplexml_load_string()` without XML validation/entity/zip-bomb safeguards, runs N+1 `SELECT`/`PREPARE` queries inside the import loop, and relies on hardcoded branch IDs.

2. **State-Changing Deletions over HTTP `GET` (lines 825–864):** `delete_eq`, `delete_web`, `delete_m365`, and `delete_tenant` execute `DELETE FROM ...` on a `GET` request (exploitable via CSRF/img tags/link prefetching).

4. **Password Trimming Bug in `save_tenant` (line 755):** `$password_plano = trim($_POST['password'] ?? '');` silently alters passwords that intentionally start or end with spaces (unlike `add_eq`, `edit_eq`, `add_web`, `add_m365`, `edit_m365`).
5. **Unvalidated URL Schemes (`save_tenant` line 757, `add_web` line 256):** `url_portal` and `url_acceso` are saved without checking `filter_var(..., FILTER_VALIDATE_URL)` or restricting to `http`/`https`.
6. **Raw Exception Leakage & Unrolled-Back Transactions (lines 865–867):** `die("Error procesando los datos: " . $e->getMessage());` exposes SQL/schema errors to the browser and does not call `$db->rollBack()` if a transaction is active.
7. **Unvalidated Input / Allowlists:** `save_tenant` inserts `$_POST['estado'] ?? 'Activo'` directly without checking an allowlist (`Activo`, `En Configuración`, `Mantenimiento`, `Inactivo`). `add_web` accesses `$_POST['plataforma']`, `$_POST['usuario']`, `$_POST['password']` without null-coalescing or empty checks.
8. **CSV Upload Risks (lines 385–744):** No file extension/MIME/size validation before `fopen()`; assumes UTF-8 without validating encoding; `import_csv_m365` (lines 627–641) does not check if `$rawHeader` is `null` before `array_flip()` and misses the second BOM regex check present in `import_csv_eq`/`import_csv_web`.

## 4. Prioritized Recommendations

1. **Eliminate Plaintext Password Exposure in HTML (Critical):** Remove `Security::decrypt()` loops and `pass_plain` from `index.php` HTML attributes (`data-password`, `json_encode` in `onclick`). Implement an authenticated, CSRF-protected AJAX endpoint (`POST`) with role checks and audit logging to decrypt and return a single password only when the user clicks "Reveal" or "Copy".
2. **Fix XSS Vulnerabilities (High):** Apply `escapeHtml()` to all fields (especially `cred.password_clear`, `cred.usuario`, `cred.tipo`, `u.nombre`, `u.sub`) in `verFichaConsolidada` and `filtrarCustomUserDropdown`; pass `JSON_HEX_TAG | JSON_HEX_APOS | JSON_HEX_QUOT | JSON_HEX_AMP` to all `json_encode()` calls; validate `http://`/`https://` schemes on `url_portal`/`url_acceso` and add `rel="noopener noreferrer"`.
3. **Fix CSRF & GET Deletions (High):** Add CSRF token verification to `guardar.php` and convert `delete_*` actions from `GET` to `POST` forms. Enforce role-based access control (RBAC) in both files.
4. **Fix the Tenants Tab Search/Filter/Pagination Bug (High):** Change `#paginacionTenants` (line 915) to `#paginacionCredenciales` (or pass `#paginacionTenants` when `$tab === 'tenants'` in `initPaginacionCredenciales()`), and fix the `rowEmpresa === ''` bypass at line 1993.
5. **Decompose `index.php` & Remove Dead Code (Medium):** Strip out the dead `equipos`, `web`, `fichas`, and `gmail` queries/HTML/modals/JS (reducing `index.php` by ~65–70% and eliminating 10+ redundant DB queries and decryptions per load). Split remaining `m365` and `tenants` views, modals, and JS into separate modular files, and remove the shadowed `abrirEditarM365` / `#modal-editar-m365` duplicate.
6. **Harden `guardar.php` & `Security` (Medium):** Extract shared CSV import and employee-resolution helpers; stop trimming Tenant passwords; preserve BitLocker keys if blank on edit; wrap exceptions with `rollBack()` and generic error messages; move the AES key out of source control and add HMAC authentication (or use `sodium_crypto_secretbox`).

## 1. Cross-Cutting Findings (All Modules)

- **No CSRF Protection**: None of the forms or state-changing endpoints use CSRF tokens. Furthermore, every delete operation across all 3 modules (`delete_dispositivo`, `delete_boveda`, `delete_it_user`, `delete_subred`, `delete_wifi`, `eliminar`, `delete_impresora`) is executed via `HTTP GET`.
- **No Role-Based Access Control (RBAC)**: Every file only verifies `isset($_SESSION['user_id'])`. Any logged-in user (e.g., `Soporte` or `Desarrollo`) has unrestricted read/write/delete access to all decrypted vault credentials, network hardware passwords, Wi-Fi keys, ISP circuits, printers, and `equipo_it` user accounts (including `Administrador` accounts).
- **Symmetric Encryption Weaknesses (`config/security.php`)**:
  - `Security::encrypt()` / `Security::decrypt()` uses `AES-256-CBC` with a **hardcoded static hex key** committed in `config/security.php` (line 10) and **no authentication tag / HMAC** (despite the Bóveda UI badge claiming `AES-256 GCM` on `infraestructura/index.php` line 743).
  - Plaintext secrets are decrypted in bulk on page load and embedded directly in the HTML DOM (`hidden` spans, `onclick` handlers, `json_encode(...)` payloads, and even `data-search` attributes).
- **Redundant Dead Flash-Message Blocks**: `includes/header.php` (lines 381–409) renders and `unset()`s `$_SESSION['flash_success']` and `$_SESSION['flash_error']` immediately when included. As a result, the secondary flash banners in `infraestructura/index.php` (lines 340–354), `internet/index.php` (lines 144–164), and `impresoras/index.php` (lines 97–111) never execute.
- **Raw Database Error Exposure**: All three `guardar.php` controllers catch `PDOException` / `Exception` and surface raw `$e->getMessage()` into flash errors or JSON responses, leaking SQL table/column/constraint details.
- **SQL Injection Posture**: All database queries across all 6 files are either static `$db->query(...)` strings or PDO prepared statements (`prepare`/`execute`) with `?` placeholders. **No SQL injection vulnerabilities were found** in these 6 files.

## 4. Specific Assessment: Is the Wi-Fi Module Working Correctly?

**Basic CRUD works, but there are 4 concrete functional/security bugs:**

1. **Broken Wi-Fi QR Code Payload (`infraestructura/index.php` lines 2650–2651)**:
   - `mostrarQrWifi()` builds `WIFI:S:${encodeURIComponent(ssid)};T:WPA;P:${encodeURIComponent(pass)};;` and then calls `encodeURIComponent(qrData)` a **second time** when building the QR URL. Any SSID or password containing spaces or special characters (such as `!@#$%&*` generated by `generarPasswordWifi()`) gets percent-encoded inside the `WIFI:` string (e.g., `%21%40`), breaking mobile QR auto-connect.
   - Additionally, `T:WPA` is hardcoded even when `seguridad` (passed as an unused argument to `mostrarQrWifi`) is WEP or Open.
2. **External Leakage of Wi-Fi Credentials in QR Generation (line 2651)**:
   - QR codes are generated by sending plaintext SSID and password in a GET query string to `https://api.qrserver.com/v1/create-qr-code/...`. This leaks internal Wi-Fi credentials to a third-party service and fails in offline/intranet environments.
3. **Hardcoded Company Filter Chip Mismatch (lines 1316–1324)**:
   - Same bug as `impresoras`: hardcodes `'SUMINISTROS INTEGRALES'`, `'MASTERTEC'`, and `'CENTRO DE PINTURA'` instead of querying `empresas`. Fails to match if the company is named `'Suministros'`.
4. **Plaintext Passwords in Search Attribute & Trimmed Passwords**:
   - Line 1430 includes `$rw['pass_plain']` inside `<tr data-search="...">`, exposing decrypted Wi-Fi passwords in plain DOM attributes.
   - `guardar.php` line 530 applies `trim()` to `password_wifi`, altering passwords with intentional leading/trailing spaces.
   - Like `impresoras`, the Wi-Fi table lacks `TablePaginator` and an empty-filter row when JS filters match 0 records.

6. DATABASE DESIGN, NORMALIZATION & FOREIGN KEY INTEGRITY
--------------------------------------------------------------------------------
* Normalization & Design Issues:
  - Redundant transitive FK in `proveedores_internet`: stores both `empresa_id` and `sucursal_id` even though `sucursal_id -> sucursales.empresa_id` already determines `empresa_id`; no DB constraint prevents cross-company mismatch if a branch is reassigned.
  - Denormalized string references instead of FKs: `equipos.registrado_por`, `asignaciones` (`entregado_a`, `devuelto_por`, `asignado_por`, `recibido_por`), and `recepciones_equipos` (`entregado_por`, `recibido_por`, `receptor_final`, `creado_por`) store free-text names instead of foreign keys to `empleados`/`equipo_it`.
  - Free-text attributes: `empleados.cargo` and `empleados.departamento` lack lookup tables, leading to inconsistent strings (e.g., `'IT'` vs `'Tecnología'`).
  - Missing UNIQUE constraints: `empresas.nombre`, `sucursales(empresa_id, nombre)`, `credenciales_equipos(equipo_id)` (1:1 assumed in `modules/credenciales/index.php:28`), `impresoras.numero_serie`, `redes_wifi(sucursal_id, ssid)`, and `tenants.correo` / `tenants.tenant_id_cloud`.
  - Missing indexes on frequently filtered columns: `empleados.estado`, `asignaciones.fecha_devolucion`, `cuentas_m365.estado`, `impresoras.estado`, `proveedores_internet.estado`.

* Foreign Key Integrity:
  - `sucursales.empresa_id -> empresas(id) ON DELETE CASCADE` conflicts indirectly with `empleados.sucursal_id` and `equipos.sucursal_id` (`ON DELETE RESTRICT`), causing cascading company deletes to fail if any branch still has employees/equipment (prevented only by PHP check on `sucursales` in `guardar_sucursales.php`).
  - `impresoras`, `redes_wifi`, `proveedores_internet`, and `subredes` all declare `ON DELETE CASCADE` on `sucursal_id`, yet `guardar_sucursales.php?action=eliminar_sucursal` does not check those tables—causing silent cascade deletion of printers, Wi-Fi networks, ISP links, and subnets when a branch is deleted.
  - `asignaciones` uses `ON DELETE CASCADE` for both `equipo_id` and `empleado_id`, which erases historical audit trails if a hard delete occurs.
  - `credenciales_web.usuario_it_id` FK (`ON DELETE SET NULL` -> `equipo_it(id)`) is missing from all `database/*.sql` scripts.
  - `script_gestion_it.sql` fails before creating `tareas_it`'s FK (`fk_tarea_equipo_it`) and all subsequent tables due to the missing `);` at line 178.
